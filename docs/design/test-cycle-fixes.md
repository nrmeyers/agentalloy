# Design: Test Cycle Fixes for Container Entrypoint

## Overview

This design addresses two container deployment issues identified during six test cycles (3 native, 3 container) on a remote laptop:

- **Issue 3**: When `packs` is empty (user passed `-n` without `--packs`), the container entrypoint skips pack installation entirely, resulting in zero skills installed.
- **Issue 4**: Uvicorn starts BEFORE pack installation, causing a LadybugDB lock conflict (`IO exception: Could not set lock on file : /app/data/ladybug`) because the running uvicorn process holds a write lock on the database.

Both fixes are contained within a single function: `_build_entrypoint_script()` in `src/agentalloy/install/subcommands/container_runtime.py` (lines 316-491).

### Why This Design

The entrypoint is a bash script generated by Python and mounted as a read-only volume into the container. The fix requires only reordering existing code and changing one branch — no new functions, no new dependencies, no new attack surface. The change is surgical and low-risk.

### Key Differences

| Aspect | Current (Broken) | After Fix |
|--------|-----------------|-----------|
| Uvicorn start | Before pack install (line 439) | After pack install + bootstrap complete |
| Empty packs | `echo "No packs specified - skipping"` | `uv run agentalloy install-packs --non-interactive --no-restart` |
| Lock conflict | uvicorn holds lock during pack install | No uvicorn during pack install — no conflict |
| `/readiness` during bootstrap | Available (warming_up) | Not available until bootstrap completes |
| Initial wait time | Shorter (uvicorn starts immediately) | Longer (pack install + bootstrap before uvicorn) |

"""Build the entrypoint wrapper script (fast-start + checkpointed).

Compared to the original "bootstrap then exec uvicorn" pattern, this
script:

1. Creates `.bootstrap-lock` with an ISO timestamp at the start of a
   new bootstrap; removes it and creates `.bootstrap-complete` when
   done. The host-side `/readiness` endpoint reads these markers.

   (atomic temp + mv) before each pack, and appends a checkpoint line to
   ``.bootstrap-checkpoints`` after each pack succeeds.
5. On restart, parses the checkpoint file and skips packs already
   recorded — partial bootstrap crashes resume from where they left off.
   A corrupted checkpoint file is treated as "no checkpoints" so the
   script never fails closed on a malformed line.
"""

## Sequence Diagram

### New Entrypoint Sequence

```
Container Start
    |
    | 1. Stale lock recovery (if lock > 2h, wipe and start fresh)
    v
  Check .bootstrap-complete
    |
    +-- EXISTS --> Skip all bootstrap, start uvicorn directly
    |
    +-- MISSING --> Continue bootstrap
    v
 2. Record bootstrap start (write .bootstrap-lock)
    v
 3. Install Ollama (if not present)
    v
 4. Start Ollama serve on 127.0.0.1:11434 (background)
    v
 5. Wait for Ollama (poll 30s)
    v
 6. Pull embedding model (if not cached)
    v
 7. Run migrations (uv run python -m agentalloy.migrate)
    v
 8. Pack installation:
    |
    +-- packs specified --> Per-pack loop with checkpoints
    |
    +-- no packs --> agentalloy install-packs --non-interactive --no-restart
    v
 9. Mark bootstrap complete (rm lock, touch .bootstrap-complete)
    v
10. Start uvicorn on 0.0.0.0:47950 (background)
    v
11. Wait for uvicorn (container exit = uvicorn exit)
```

### Contrast with Current (Broken) Sequence

```
Container Start
    |
    | 1-7. Same as new sequence (Ollama, model, migrations)
    v
 8. Start uvicorn <-- PROBLEM: uvicorn now holds LadybugDB write lock
    v
 9. Pack installation <-- FAILS: "Could not set lock on file"
    v
10. Mark bootstrap complete
```

## Error Handling

### Pack Installation Failure

- **Per-pack loop (explicit `--packs`)**: The existing `set -e` at the top of the script causes the entrypoint to abort on any non-zero exit from `agentalloy install-packs`. The lock file remains, so the next restart will retry from the checkpoint.
- **Always-on packs (empty `--packs`)**: Same `set -e` behavior. If `agentalloy install-packs --non-interactive --no-restart` fails, the entrypoint aborts and the lock persists.

### Ollama Installation Failure

- Unchanged from current behavior. If `curl` or `ollama serve` fails, `set -e` aborts the entrypoint.

### Migration Failure

- Unchanged. If `uv run python -m agentalloy.migrate` fails, `set -e` aborts.

### Uvicorn Start Failure

- New behavior: If uvicorn fails to start (port in use, Python error), `set -e` will NOT catch it because uvicorn is started with `&` (background). The script will reach `wait $UVICORN_PID` and the `wait` will return the background process's exit code, causing the container to exit.
- The SIGTERM trap still works because it's set before the uvicorn start.

### Stale Lock Recovery

- Unchanged. The existing check at lines 361-371 detects locks older than 2 hours and wipes them. This works identically in the new sequence because the lock file is still created at the same point (start of bootstrap).

## Performance Considerations

### Increased Initial Wait Time

- **Current**: Uvicorn starts immediately after migrations (~10-30s on fast hardware). The `/readiness` endpoint is available during pack installation.
- **After fix**: Uvicorn starts only after pack installation completes. With always-on packs (5 packs), this adds ~2-5 minutes. With explicit packs, it adds the time for all specified packs.

### Impact on `/readiness` Endpoint

- **Current**: `/readiness` reports `warming_up` during pack install because uvicorn is already running.
- **After fix**: `/readiness` is NOT reachable until bootstrap completes. The host-side `_wait_for_readiness()` function in `container_runtime.py` (line 584) already handles this — it polls the URL and retries on connection errors for up to 1800 seconds (30 min). The grace window of 1800s at line 631 is sufficient for full pack ingest + re-embed.

### Impact on `/health` Endpoint

- `/health` is served by uvicorn, so it follows the same availability pattern as `/readiness` — not available until uvicorn starts.
- This is acceptable: `/health` is a dependency check, not a bootstrap progress indicator. The host uses `/readiness` for bootstrap state.

### No Performance Degradation After Bootstrap

- Once bootstrap is complete, the container behavior is identical to before. Subsequent restarts detect `.bootstrap-complete` and start uvicorn immediately.

## Security

### No New Attack Surface

- The fix does not introduce any new external dependencies, network calls, or file paths.
- `agentalloy install-packs --non-interactive --no-restart` is the same command used in the native setup flow.
- The `--no-restart` flag ensures the install-packs subcommand does not attempt to restart the service (which would conflict with the entrypoint's own uvicorn management).

### No Data Exposure

- The entrypoint script is mounted as a read-only volume (`:ro`) into the container at `/app/entrypoint.sh`.
- No sensitive data is written to the script.

### Backward Compatibility

- Existing containers with `.bootstrap-complete` already present will skip bootstrap entirely and start uvicorn directly. This is correct and unchanged.
- Containers with stale locks will be recovered and re-bootstrapped.
- The new entrypoint script is functionally equivalent for the "packs already installed" case.

## Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Longer initial wait | LOW | Grace window of 1800s in `_wait_for_readiness()` handles full bootstrap |
| `/readiness` unavailable during bootstrap | LOW | `_wait_for_readiness()` retries on connection errors |
| Pack installation failure aborts bootstrap | LOW | `set -e` + lock file ensures retry on next restart |
| No regression in existing tests | MEDIUM | Test plan includes updating existing test expectations |
| Stale lock detection | LOW | Unchanged logic, lock file position unchanged |
