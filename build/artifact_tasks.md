# v2-local-agent-mvp — Plan (M1, local agent)

Vertical slices in dependency order, each leaving `just ci` green. Each task names the spec ACs it satisfies and the design § it implements. T4 is a **gate**: it must pass before T8 starts. T11 is conditional on T2's spike outcome (build marks it done/no-op if the primary ColBERT path works).

**R1 (user-approved 2026-09-03; recorded in revision-note.artifact):** the ENTIRE interpreter surface is MCP-shaped tool-calling — every read + state action is a tool with a JSON-Schema `inputSchema` presented via the `:50001` chat `tools` array (llama.cpp GBNF constrained decoding); the spike's two-stage classify→fill is retired; `none` = the model emits no tool call / final answer. T4 + T5 are scoped accordingly.

**R2 (user-approved 2026-09-03; recorded in revision-note.artifact):** `contract_read` is DROPPED — READ's `contract_detail` is the single contract-read path. The interpreter surface is **12 tools**: 9 read + 3 state (`contract_add`, `artifact_record`, `phase_advance`) — two near-identical contract-read tools in one flat list is exactly the routing confusion T4 measures on the 2.6B model. Companion plan clarification: T5's state executors target a store *interface* + fakes; the real DuckDB stores are wired at T7/T8 (TC-7.5 proves interpreter-driven persistence).
